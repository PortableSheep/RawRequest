# RawRequest Frontend

Angular 21 (standalone components) frontend for the RawRequest desktop app,
rendered inside a Wails v2 webview. For the full project architecture, see
[../docs/ARCHITECTURE.md](../docs/ARCHITECTURE.md).

## Development server

```bash
npm start
```

Runs `ng serve` at `http://localhost:4200/` with hot reload. Note that Wails
bindings (`window.go`, `window.runtime`) are only available when running
inside the actual Wails desktop shell — use `./scripts/dev-build.sh` from the
repo root for full end-to-end development against the Go backend.

## Build

```bash
npm run build
```

Builds to `dist/`. This directory is git-ignored and is **required** at Go
build time: `main.go` embeds it via `//go:embed all:frontend/dist`. Running
`go build .` / `go run .` without first building the frontend will fail (or
embed stale assets). `wails build` and `scripts/build.sh` handle this for
you; see [../docs/ARCHITECTURE.md](../docs/ARCHITECTURE.md#frontenddist--build-output-required-for-go-builds)
for details.

## Tests

Tests use [Vitest](https://vitest.dev), not Karma/Jasmine or Jest:

```bash
npm test              # single run (vitest run)
npm run test:watch    # watch mode (vitest)
```

Test files are `*.spec.ts`, co-located with the code under test.

## Code organization

* **`*.logic.ts`**: Pure, unit-testable, deterministic logic with a matching
  `*.logic.spec.ts`. Prefer putting business logic here over inside
  components.
* **`*.component.ts`**: UI components that orchestrate logic and interact
  with Wails bindings. Keep components small (~200 lines); extract distinct
  responsibilities into services or sub-components.
* **`src/app/services/`**: Injectable services, including ones extracted from
  components that manage cross-cutting state (layout, keyboard shortcuts,
  panel visibility, request execution).
* **`src/app/logic/`**: Feature-organized logic modules (app, active-run,
  history, layout, request, ...).
* **CodeMirror 6**: Powers the `.http` file editor, with custom lezer
  grammars for syntax highlighting and linting.
* **Styling**: SCSS.

## Wails bindings (`wailsjs/`)

`src/../wailsjs/` (`wailsjs/go/app/App.{d.ts,js}`, `wailsjs/go/models.ts`,
`wailsjs/runtime/`) is **generated by the Wails CLI** from the Go `App`
struct's exported methods, and is regenerated automatically by `wails dev` /
`wails build` (and `scripts/dev-build.sh` / `scripts/build.sh`). Import from
`@wailsjs/go/app/App` in application code, but never hand-edit or manually
patch files under `wailsjs/` — if bindings look stale, regenerate them by
running Wails rather than editing the generated output.
